# CAM AI on the reference library: every program

CAM AI on each of the 108 distinct programs of the reference library (all have a 3D model), next to the engineers' program read the same way: `npm run cam-library -- <library> <out.jsonl>` (`tools/camLibrary.ts`). CAM AI at commit cfa556d; the three programs marked * at 6bc5081, which fixed a crash on them. The findings: `docs/knowledge/cam-gaps.md`.

- **Each cell:** clampings / lines / minutes.
- **Match:** the simulated part against the 3D model (1 = the same).
- **Collisions:** what CAM AI's own check finds (tool or holder into jaws, parallels or part; rapids into material). The app locks such programs.
- **Off at stop / fixed jaw (mm):** in the later clampings, the most the faces the vise really holds (between the parallels and the jaw tops) lie inside the size written for the clamping, at the X stop and at the fixed jaw. The program puts the written size there, so on the machine the part sits that far off (gap P1). The match does not show it: the simulation places the part by the written size. The figures come from the app's reading of each clamping and are not checked by hand; the largest ones especially should be.
